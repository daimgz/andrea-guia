    Clase 2: git, spring y jpa¶

    Temas: * git (checkout, init y commit) * usar maven para crear proyecto spring * layers: * entity (ver como usarlo con jpa) * repository (ver como usarlo con jpa) * service (tal vez más ejemplos de business logic) * controller (se mantiene lo mismo, quizas se vea que logica se pone acá y cual en controller)

    Breve descripción de lo que se verá en esta clase.

    Comandos básicos de Git¶

    Configuración inicial¶

    • Configurar nombre y correo del usuario: git config --global user.name "Tu Nombre" git config --global user.email "tuemail@ejemplo.com"

    • Ver configuración: git config --list

    Crear y clonar repositorios¶

    • Crear un repositorio nuevo en la carpeta actual: git init

    • Clonar un repositorio remoto: git clone

    Estado y cambios¶

    • Ver estado de archivos modificados, nuevos o eliminados: git status

    • Ver diferencias entre archivos modificados y última versión commit: git diff

    Añadir y commit¶

    • Añadir archivos para preparar commit: git add # un archivo específico git add . # todos los cambios

    • Crear commit con mensaje: git commit -m "Mensaje del commit"

    Ramas (branches)¶

    • Ver ramas existentes: git branch

    • Crear una rama nueva: git branch

    • Cambiar a otra rama: git checkout

    • Crear y cambiar a una rama nueva al mismo tiempo: git checkout -b

    Trabajando con remoto¶

    • Ver remotos configurados: git remote -v

    • Traer cambios desde el remoto (fetch + merge): git pull origin

    • Subir cambios al remoto: git push origin

    Otros comandos útiles¶

    • Ver historial de commits: git log

    • Descartar cambios en un archivo: git checkout --

    • Eliminar archivo del seguimiento de Git (sin borrar local): git rm --cached

    Entidades¶

    @Table y @Entity¶

    @Entity Marca una clase como entidad persistente. @Table Define el nombre de la tabla y configuraciones adicionales.

    @Entity
@Table(name = "users")
public class User {
}

    @Id y @GeneratedValue¶

    @Id Define la clave primaria. @GeneratedValue Define cómo se genera automáticamente el id.

    @Id
@GeneratedValue(strategy = GenerationType.IDENTITY)
private Long id;

    Estrategias comunes:

    Estrategia Cómo funciona Ventajas Desventajas Uso típico
    AUTO JPA elige automáticamente la estrategia según la base de datos (puede ser SEQUENCE, IDENTITY o TABLE) Portabilidad entre bases, simple de usar Comportamiento puede variar según la base de datos Aplicaciones portables entre distintos motores
    IDENTITY La base de datos genera el valor automáticamente (auto-increment) al insertar la fila Simple y rápido, no requiere consultas adicionales No funciona bien con batch inserts en algunas JPA MySQL, SQL Server, PostgreSQL
    SEQUENCE JPA obtiene el próximo valor de una secuencia de la base de datos antes de insertar Permite preasignar IDs, eficiente para batch inserts Requiere soporte de secuencias en la base de datos Oracle, PostgreSQL
    TABLE JPA simula una secuencia usando una tabla especial que almacena el último valor generado Funciona en cualquier base, portable Más lento, requiere tabla adicional, más complejidad Bases que no soportan secuencias (por ejemplo, algunos SQLite antiguos)

    Columnas¶

    @Column¶

    Configura propiedades de una columna. Muy importante recordar que no es estrictamente necesario rellenar el campo "name". Se rellena generalmente cuando va a ser diferente el nombre del atributo de la clase on comparacion con el nombre de la columna. Por convencion las columnas de las db deben usar snake case (o sea usar "_" para separar las palabras) y los atributos de la clase deben ser cammel case (o sea separado usando mayusculas). db: created_at entity: createdAt

    @Column(nullable = false, unique = true, length = 100)
private String email;

@Column(name = "created_at", nullable = false, unique = true, length = 100)
private String createAt;

    Opciones comunes:

    • nullable
    • unique
    • length
    • name

    @Transient¶

    Es un campo que por algun motivo necesitamos dentro de la clase, pero que no esta en la tabla de la db.

    @Transient
private String calculatedValue;

    @Enumerated¶

    Define cómo se persiste un enum.

    @Enumerated(EnumType.STRING)
private Status status;

    Opciones:

    • STRING
    • ORDINAL

    @Lob¶

    Para almacenar datos grandes. En la clase habíamos visto que se usaba @Column(columnDefinition = "TEXT"), lo cual no es incorrecto, pero @Lob es más portable. Al poner columnDefinition estás especificando exactamente el tipo que tendrá la base de datos, pero para textos grandes existen varios tipos dependiendo del motor de base de datos (SQLite, MariaDB, etc.).

    Al usar @Lob, si cambias de motor de base de datos, el código de la entity queda exactamente igual. En cambio, si usas columnDefinition, tenés que cambiar el tipo al cambiar de base de datos.

    En pocas palabras, casi siempre se recomienda usar @Lob.

    @Lob
private String description;

@Lob
private String content;

    Relaciones¶

    @ManyToOne¶

    • Muchos de esta entidad → uno de la otra.
    • Ejemplo: muchos Article → un User
    • Opciones importantes: fetch = LAZY | EAGER 
      @ManyToOne(fetch = FetchType.LAZY)
@JoinColumn(name = "user_id")
private User author;

    @OneToMany¶

    • Uno de esta entidad → muchos de la otra (inversa de @ManyToOne)
    • Ejemplo: un User tiene muchos Article 
      @OneToMany(mappedBy = "author", fetch = FetchType.LAZY, cascade = CascadeType.ALL)
private List<Article> articles;

    @OneToOne¶

    • Uno a uno entre entidades
    • Ejemplo: un User tiene un Profile 
      @OneToOne(fetch = FetchType.LAZY)
@JoinColumn(name = "profile_id")
private Profile profile;

    @ManyToMany¶

    En una relación Many-to-Many bidireccional, ambas entidades pueden tener la lista de la otra, pero solo una controla la relación.

    Ejemplo: un Student tiene muchos Course y un Course tiene muchos Student.

    @Entity
public class Student {
    @Id
    private Long id;

    @ManyToMany
    @JoinTable(
        name = "student_course",
        joinColumns = @JoinColumn(name = "student_id"),
        inverseJoinColumns = @JoinColumn(name = "course_id")
    )
    private List<Course> courses;
}

@Entity
public class Course {
    @Id
    private Long id;

    @ManyToMany(mappedBy = "courses")
    private List<Student> students;
}

    Conceptos clave¶

    • Controlar la relación significa que solo la entidad que define @JoinTable decide cómo se guarda la relación en la tabla intermedia.
    • La otra entidad (mappedBy) no crea la tabla, solo refleja los datos.
    • Esto evita duplicar tablas intermedias y mantiene sincronizadas las listas de ambas entidades.
    • La entidad que controla puede hacer persist/remove sobre la relación; la inversa se actualiza automáticamente en memoria si se usan listas sincronizadas.
